# Privacy Policy Draft

## Purpose

This document is the draft baseline for Ascend's public privacy policy.

## Data Ascend Uses

Ascend currently uses data required to operate the product:

- authentication identity from Firebase Auth
- player progression data
- quests and completion state
- competitive progression and integrity read-models
- analytics events for product and funnel reading
- crash data for stability and operational diagnosis

## Why The Data Is Used

Data is used to:

- let the user sign in and restore access
- save progression and quest state
- compute competitive status and season behavior
- understand first-session and retention friction
- diagnose crashes, remote failures, and regressions

## Data Minimization Direction

Ascend should only keep data that is needed for:

- account access
- progression continuity
- competitive integrity
- release operations

Ascend should not treat personal data as a monetizable asset.

## Analytics And Crash Reporting

Ascend currently uses:

- Firebase Analytics for product telemetry
- Firebase Crashlytics for fatal and non-fatal error reporting

These systems exist to improve reliability, measure funnel health, and understand where users are failing or dropping.

## Competitive Integrity

Competitive systems may use:

- authoritative quest session/grant records
- activity history
- integrity/trust signals

These are used to protect the fairness of rank, boss, and seasonal systems.

## User Rights Direction

Before wider public distribution, the public policy should clearly explain:

- what data is stored
- how a user requests support
- how a user requests deletion of account-linked data
- expected response window for operational requests

## Public Release Requirement

Before public beta or store launch:

- publish a public-facing version of this policy
- link it from the app account surface
- link it from the store listing and support surface
